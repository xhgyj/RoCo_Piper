# 任务 C：PLACE_UP 前置 PICK 抓取区域实现

日期：2026-10-13。远端仓库：`/home/mzictt/RoCo_Piper`。

## 本次修改

- `PICK(successor_skill=PLACE_UP)` 不再调用 Python 的 16 个固定姿态候选循环。
- 新增内部目标 `grasp_region`，绑定真实砖块位姿、机器人基座、TCP 标定、指垫几何和张开宽度。外部 robot-operation-plan 格式不变。
- 接近仍只有一次公共空间运动：张开 → combined plan 到低位抓取边界 → 闭合 → lift。没有侧向清障路径、额外 TRANSIT 或高位下降段。
- 普通 PICK 仍使用原来的目标生成和执行流程。

## 接口与职责

`skills/grasp_region.py`：读取现有 hash-pinned TCP 标定的接触面顶点；构造砖块局部坐标下的可抓区域；校验场景绑定、规划终点和实测终点；按实际姿态确定闭合宽度及 lift。

`coordinated_session_entry.py`：包含区域目标的请求不再先求单臂固定姿态 IK，也不注入固定关节终态。混合请求里的精确 TCP 目标一起交给 MoveIt。执行前使用既有 compute_tcp_fk 接口核对规划终点，FK 只查询模型、不发送动作。

`coordinated_ros_runtime.py`：生成一个 dual_arm 目标，可包含单臂抓取区域、两个抓取区域、精确 TCP 或保持臂。未参与执行的会话臂由实测关节状态保持，返回轨迹逐点核对保持约束。

`grasp_region_sampler.hpp`：在 MoveIt 内连续采样侧向/斜向俯仰、四组侧面方向及夹爪对称方向，并联合处理另一臂目标。保留真实关节限位、IK、FK、碰撞检查和 MoveIt 有效性回调。路径仍由同一个双臂规划请求生成。

## 几何边界

- 两指闭合轴对应砖块相对侧壁；TCP 位于指垫可以夹持的区域。
- 接触面包络不穿过地面；机器人与砖块、地面、底板和附着物的碰撞继续由 MoveIt 模型检查。
- 不采用垂直顶抓/穿地底抓；手掌位置不能占据砖块上方连接区域。
- 接近途中不允许夹爪提前碰砖；只有真实到达、实测抓取几何通过后才开放必要的指垫接触。
- 规划终点与实际到达都不是 holding 证据。闭合、lift 和真实跟随确认保留原逻辑。

## 后继继承

## 实测后的 FK 输入修复

首次带画面运行中，MoveIt 已成功生成双臂路径，但规划终点校验报出 `grasp region endpoint FK is unavailable`，接近/闭合/lift 尚未执行。原因是适配器把双臂状态中的 mimic 父变量 `gripper` 一并传入严格接受 8 个实际关节的 FK 接口，在本地输入校验阶段被拒绝。

现已修复：规划状态保持不变；FK 输入只从完整规划终态提取 `JOINT_NAMES` 的 8 项，缺失任何真实关节仍明确拒绝。新增测试对两台机器人使用生产 `state_is_complete` 判定，并检查规划终态覆盖与父变量保留。相关回归最终 209 项通过。该修复后未代用户启动仿真，实际执行由用户验证。
